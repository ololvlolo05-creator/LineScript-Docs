# Спецификация языка LineScript (версия 1.1)

Настоящий документ является нормативной спецификацией языка разметки команд **LineScript** версии 1.1.

---

## 1. Введение и назначение

**LineScript** — легковесный текстовый язык структурированной разметки команд, спроектированный для надёжной передачи инструкций от удалённых агентов (включая большие языковые модели (LLM), веб-приложения и распределённые службы) к локальному доверенному исполнителю.

Язык решает три ключевые проблемы межсистемного взаимодействия:
1. **Устойчивость к Markdown и экранированию веб-интерфейсов**: стандартные спецсимволы (`>`, `*`, `_`, `$`, backticks) не разрушают структуру команд.
2. **Линейная потоковая обработка**: команды могут выполняться последовательно без необходимости сложного абстрактного синтаксического дерева (AST).
3. **Безопасная изоляция**: команды явно разделены по типам (`cmd`, `ps`, `file`, `patch`, `file-bin`), что позволяет исполнителю валидировать и изолировать операции.

---

## 2. Общие соглашения

### 2.1 Кодировка
Все документы и потоки LineScript должны кодироваться исключительно в **UTF-8 без маркера последовательности байтов (BOM)**. Окончания строк допускаются как `\n` (LF), так и `\r\n` (CRLF).

### 2.2 Нечувствительность к регистру тегов
Идентификаторы типов команд нечувствительны к регистру: `-cmd-` эквивалентно `-CMD-` и `-Cmd-`.

---

## 3. Формальная грамматика (EBNF)

```ebnf
Stream          ::= [ Preamble ] { CommandBlock } [ Epilogue ] ;

CommandBlock    ::= [ StepIndex ] CommandTag Body Terminator ;

StepIndex       ::= "[" Digit { Digit } "]" ;

CommandTag      ::= "-" Identifier "-" ;

Identifier      ::= Letter { Letter | Digit | "-" | "_" } ;

Terminator      ::= "-/-" ;

Body            ::= { EscapedChar | AnyCharExceptTerminator } ;

EscapedChar     ::= "\--/-\-" ;

AnyCharExceptTerminator ::= ? Любой символ UTF-8, за исключением подстроки "-/-" ? ;

Letter          ::= "a" ... "z" | "A" ... "Z" ;
Digit           ::= "0" ... "9" ;
```

---

## 4. Лексическая структура

### 4.1 Тег команды (`CommandTag`)
Команда начинается с дефиса, за которым следует идентификатор типа и закрывающий дефис:
```text
-тип-
```
Примеры: `-cmd-`, `-ps-`, `-file-up-`, `-file-bin-`, `-patch-`.

### 4.2 Порядковый индекс (`StepIndex`)
Перед тегом команды допускается опциональный порядковый номер в квадратных скобках:
```text
[1] -ps- Get-Date -/-
[2] -cmd- dir -/-
```
Исполнитель должен выполнять пакетные команды в порядке возрастания указанных индексов. Если индекс опущен, сохраняется естественный порядок появления в потоке.

### 4.3 Терминатор (`Terminator`)
Каждая команда строго завершается последовательностью символов:
```text
-/-
```
Наличие пробелов до или после терминатора не влияет на его распознавание.

### 4.4 Экранирование внутри тела
Если тело команды обязано содержать последовательность символов `-/-`, источник обязан экранировать её как:
```text
\--/-\-
```
При разборе исполнитель производит замену `\--/-\-` -> `-/-` перед передачей аргументов в подсистему выполнения.

---

## 5. Стандартные типы команд (Core Registry)

| Тип команды | Описание | Формат тела |
|-------------|----------|-------------|
| `-cmd-` | Выполнение команды Windows Command Prompt (`cmd.exe`) | `<строка_команды>` |
| `-ps-` | Выполнение PowerShell скрипта | `<скрипт_powershell>` |
| `-git-` | Выполнение подкоманды Git | `<аргументы_git>` |
| `-file-` | Чтение текстового файла (целиком или диапазон) | `<путь>[\n<start>-<end>]` |
| `-file-up-` | Создание или перезапись текстового файла (с бэкапом) | `<путь>\n<содержимое>` |
| `-file-bin-` | Создание или чтение бинарного файла через Base64 | `<read\|write>\n<путь>[\n<base64>]` |
| `-del-file-` | Безопасное удаление файла (с перемещением в бэкап) | `<путь>` |
| `-patch-` | Контекстное наложение патча (блоки SEARCH/REPLACE) | `<путь>\n<<<<<<< SEARCH\n...\n=======\n...\n>>>>>>> REPLACE` |
| `-grep-` | Поиск подстроки по содержимому файлов | `[<путь>\n]<искомый_текст>` |
| `-undo-` | Откат файла к предыдущей резервной копии | `<путь>` |
| `-cd-` | Смена рабочей директории сеанса | `<путь>` |
| `-list-workspaces-` | Запрос зарегистрированных рабочих областей | *(пусто)* |
| `-add-command-` | Регистрация пользовательского макроса/команды | `<имя>\ntemplate: <шаблон>\nenvironment: <PS\|CMD>` |
| `-server-` | Запрос системного статуса исполнителя | *(пусто)* |
| `-help-` | Получение встроенной справки по командам | *(пусто)* |

## 6. Бинарные данные (`-file-bin-`)

Команда `-file-bin-` обеспечивает передачу и сохранение бинарных файлов (изображения, библиотеки, исполняемые файлы) без повреждения кодировок:

### Запись бинарного файла:
```text
-file-bin-
write
assets/logo.png
iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mNk+M9QDwADhgGAWjR9awAAAABJRU5ErkJggg==
-/-
```

### Чтение бинарного файла:
```text
-file-bin-
read
assets/logo.png
-/-
```
В ответ исполнитель возвращает размер файла и закодированное Base64 содержимое.

## 7. Модель ответов и статусов (Response Protocol)

Исполнитель возвращает статус завершения каждой команды в стандартизованном формате:

### Успешное выполнение:
```text
[STATUS: OK] [EXIT: 0]
<вывод команды>
```

### Ошибка:
```text
[STATUS: ERROR: <код_ошибки>] [EXIT: <exit_code>]
<текст ошибки / трассировка>
```

Стандартные коды ошибок:
- `ERR_FILE_NOT_FOUND`: Файл или директория не найдены.
- `ERR_PATCH_MISMATCH`: Контекстный блок SEARCH не совпал с содержимым файла.
- `ERR_TIMEOUT`: Превышено максимальное время выполнения команды.
- `ERR_SYNTAX`: Нарушен синтаксис команды LineScript.
- `ERR_ACCESS_DENIED`: Отказано в доступе по политике безопасности или правам ОС.

## 8. Совместимость с версией 1.0

Версия 1.1 полностью обратно совместима с кодом LineScript версии 1.0:
- Добавлена поддержка экранирования `\--/-\-`.
- Добавлена стандартная команда `-file-bin-`.
- Зафиксирована поддержка порядковых индексов `[N]`.
