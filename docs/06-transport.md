# 06. Транспортный уровень (Transport Protocol)

Язык LineScript абстрагирован от конкретного канала связи. Он может передаваться через веб-сокеты, именованные каналы (Named Pipes), стандартный ввод/вывод (stdio) или сохраняться в файлах `.ls`.

---

## 1. Конверты сообщений (Envelopes)

Для изоляции командного блока в потоке неструктурированного текста (например, в диалоге с языковой моделью) используются маркеры начала и конца пакета:

```text
[DS_BRIDGE_START]
-cd- C:\MyProject -/-
-ps- dotnet test -/-
[DS_BRIDGE_GATHER]
```

### Правила обработки конверта:
1. **`[DS_BRIDGE_START]`**: Обозначает начало пакета команд. Весь предшествующий текст (рассуждения модели, вступительные реплики) отсекается исполнителем.
2. **`[DS_BRIDGE_GATHER]`**: Обозначает завершение пакета и сигнал исполнителю собрать результаты выполнения всех инструкций в единый ответ.
3. Если конверт отсутствует, исполнитель парсит любые блоки `-тип- ... -/-` напрямую.

---

## 2. Поддерживаемые протоколы

### 2.1 WebSocket (DeepSeekBridge Protocol)
Используется для прямого соединения между браузерным расширением и локальным сервером:
* Порт по умолчанию: `ws://127.0.0.1:8765`
* Расширение перехватывает сгенерированный чатом блок `[DS_BRIDGE_START] ... [DS_BRIDGE_GATHER]` и отправляет его серверу в виде JSON или сырого текстового пакета.

### 2.2 Файловый транспорт (`.ls`)
Скрипты LineScript сохраняются в файлах с расширением `.ls`. Они могут исполняться пакетно:
```powershell
LineScriptTerminal.exe script.ls
```

### 2.3 Стандартный ввод/вывод (Stdio / Pipes)
Поддерживается конвейерная передача:
```powershell
Get-Content script.ls | LineScriptTerminal.exe --pipe
```
